# 목록 화면·테이블 디자인 규칙

> 2026-09-05 사용자 피드백 반영. 새 목록과 기존 목록 수정 시 함께 지키는 공통 계약이다.
> 숫자를 작게 만들거나 배지를 크게 만드는 방식으로 가독성을 해결하지 않는다.

상위 계약: [디자인 시스템](frontend-design-system.md), [프런트엔드 구조](frontend-architecture.md).
이 문서의 목록·정렬·순번 규칙은 이전 인수인계 문서의 상충하는 설명보다 우선한다.

## 1. 화면의 읽는 순서

페이지 제목·설명 → 검색조건과 조회·조건 초기화 → 목록 제목 → 열 제목·데이터 → 페이지네이션.

- 제목 아래 장식용 구분선이나 빈 영역을 추가하지 않는다.
- 본문은 사이드바를 제외한 공간에서 중앙 정렬한다. 최대 폭 1400px, 모바일 좌우 16px, md 이상 28px을 유지한다.
- 페이지 블록 간격은 `Main`의 20px로 통일한다. 개별 페이지에서 여백을 덧붙이지 않는다.
- 표와 페이지네이션은 하나의 패널이다. 페이지네이션을 가로 스크롤 내부에 넣지 않는다.
- 배경은 중립색, 데이터 영역은 표면색을 쓴다. 패널 반경 8px, 입력·버튼 반경 6px이다.

## 2. 열 정렬 — 헤더와 셀을 같은 축에 맞춘다

| 정보 유형      | 예                                           | 가로 정렬 | 표현 규칙                                   |
| -------------- | -------------------------------------------- | --------- | ------------------------------------------- |
| 표시 순번      | No                                           | 가운데    | 전체 조회 건수부터 내림차순                 |
| 수량·개수      | 계획수량, 재고, 예약, 항목 수, 연결 수       | 가운데    | 천 단위 구분, 단위는 수량 옆, 숫자 폭 고정  |
| 비율·진행률    | 45%, 진행 막대와 수치                        | 가운데    | 막대와 수치를 한 묶음으로 가운데 배치       |
| 날짜·시각      | 납기, 유효기간, 발생 시각, 등록일            | 가운데    | 날짜를 한 줄로 유지, 시간 값 임의 변경 금지 |
| 짧은 상태·구분 | 상태, 판정, 우선순위, 검사 구분              | 가운데    | 짧은 문자와 필요한 아이콘                   |
| 행의 실행 버튼 | 시작, 완료 입력, 판정                        | 가운데    | 행 클릭과 별개로 작동                       |
| 업무 식별자    | 작업지시 번호, LOT 번호, 검사 번호, Revision | 왼쪽      | 숫자가 포함되어도 수량이 아니라 식별자      |
| 이름·코드      | 제품명, 자재명, 제품 코드, 사용자            | 왼쪽      | 이름 먼저, 보조 코드 다음 줄                |
| 설명·내역      | 차단 사유, 사건 제목, 감사 내용, 구성 자재   | 왼쪽      | 필요한 열만 줄바꿈                          |

- 세로 정렬은 모두 가운데다. 제목만 가운데·셀은 오른쪽처럼 혼용하지 않는다.
- 숫자와 날짜에는 `tabular-nums`를 적용한다. 숫자라는 이유로 오른쪽 정렬하지 않는다.
- 제품 코드나 작업지시 번호를 숫자 열로 분류하지 않는다.
- 정렬은 `DataTableColumn.align`에 반드시 명시한다. 새 열에서 생략하면 타입 검사에 실패한다.
- 가운데 정렬 셀 안의 flex 묶음도 가운데 정렬한다. 열 안쪽에 별도 좌우 여백으로 위치를 맞추지 않는다.
- 상세 요약·입력 폼·차트는 이 표 정렬 규칙의 대상이 아니다. 그 화면의 읽기 순서와 라벨 정렬을 유지한다.

## 3. No — 조회 결과 기준 역순

No는 데이터베이스 ID도, 등록 순서를 뜻하는 업무 번호도 아니다. 현재 조회 결과의 표시 순번이다.
서버가 반환한 행 순서는 그대로 두고 No만 역순으로 계산한다.

```text
No = 조회 결과 전체 건수 - ((현재 페이지 - 1) × 페이지 크기) - 현재 페이지의 행 인덱스
```

행 인덱스는 0부터 시작한다. 전체 건수는 필터 적용 후 서버의 `total`이다.

| 전체 43건, 기본 페이지당 10건 | No 범위 |
| ----------------------------- | ------- |
| 1페이지                       | 43 → 34 |
| 2페이지                       | 33 → 24 |
| 3페이지                       | 23 → 14 |
| 4페이지                       | 13 → 4  |
| 5페이지                       | 3 → 1   |

- 검색 후 9건이면 `9 → 1`이다. 현재 페이지의 행 수로 순번을 다시 시작하지 않는다.
- 페이지를 넘겨도 No가 이어지며, 필터를 바꾸고 조회하면 새 결과의 전체 건수부터 다시 계산한다.
- 페이지를 나누지 않는 전체 목록은 `rows.length`부터 내려간다.
- No와 첫 업무 식별 열은 표 가로 스크롤 중 고정한다. 온보딩의 다른 열 안내 중에는 기존 고정 해제·복원 동작을 유지한다.

## 4. 페이지네이션

- 서버 페이지를 지원하는 8개 목록에 공용 `Pagination`을 사용한다: 작업지시, 공정 실행, 자재 LOT, 검사, 부적합·격리, 감사이력, BOM, LOT 계보.
- 결과가 한 페이지여도 표 하단을 숨기지 않는다. 총 건수, 표시 구간, 현재/전체 페이지와 `1` 버튼이 보인다.
- 기본 표시 건수는 **10건**이다. 표 하단에서 **10·20·50·100건씩 보기**를 선택한다. 선택 즉시 적용된 검색조건을 유지한 채 1페이지를 다시 조회한다. No·표시 구간·전체 페이지는 응답의 pageSize로 함께 계산한다.
- 표시 건수는 각 목록 URL의 pageSize로 보존한다. 새로고침·뒤로가기·앞으로가기에도 유지하며, 잘못된 값은 10건으로 정규화한다. 기본 10은 URL에서 생략하되 API에는 명시한다.
- 데스크톱의 페이지 이동 버튼은 표의 정중앙에 둔다. 왼쪽은 건수·표시 구간, 오른쪽은 표시 건수 선택·현재/전체 페이지다. 좌우 칸 폭을 같게 두어 글자 길이가 달라도 중앙이 흔들리지 않게 한다. 표 폭 900px 미만에서는 이동 버튼을 별도 행 중앙에 배치한다.
- 데스크톱은 처음·이전·페이지 번호 최대 5개·다음·마지막을 제공한다. 모바일은 이전·번호 최대 3개·다음으로 줄여 가로 넘침을 막는다.
- 현재 번호는 `aria-current="page"`로 알린다. 처음/끝에서 불가능한 이동과 재조회 중의 이동은 비활성화한다.
- 페이지 클릭 시 적용된 검색조건을 유지하고 URL의 `page`만 바꾼다. 아직 조회하지 않은 편집 조건을 몰래 적용하지 않는다.
- `total`과 페이지 수는 서버 응답으로 계산한다. 현재 페이지의 행만 정렬하거나 잘라 전체 페이지인 것처럼 표시하지 않는다.
- 사용자 관리에도 동일한 10·20·50·100건 선택과 페이지네이션을 적용한다. 이 API는 권한이 허용한 전체 목록을 반환하므로 전체 응답을 기준으로 클라이언트에서 나눈다. 서버가 반환한 일부 페이지만 다시 나누는 방식이 아니다.
- 빈 결과에도 표시 건수 선택을 유지한다. 범위 밖 페이지는 없는 행의 번호·구간을 만들지 않고 첫 페이지로 복구할 수 있게 한다. 오류에는 재시도를 제공한다.

## 5. 검색조건과 실제 행 정렬

- 검색어·선택 조건을 편집하는 동안 기존 결과를 유지한다.
- `조회` 또는 Enter로 한 번에 적용한다. 한글 조합을 확정하는 Enter는 조회로 처리하지 않는다.
- `조건 초기화`는 미적용 입력과 적용된 검색조건을 모두 비우고 첫 페이지를 조회한다. 표시 건수는 검색조건이 아닌 목록 표시 설정이므로 유지한다.
- 조회와 조건 초기화는 같은 위치에 유지한다. 조회 중에도 버튼을 없애거나 결과 표를 스켈레톤으로 바꾸지 않는다.
- 결과 건수와 적용 안내는 데스크톱에서 한 줄에 나란히, 좁은 화면에서는 줄을 나눠 배치한다.
- URL·새로고침·뒤로가기·앞으로가기가 적용된 조건과 일치해야 한다.
- **열의 가운데/왼쪽 정렬과 행의 오름차순/내림차순 정렬은 서로 다르다.** 이번 변경은 셀 배치와 No 역순이다. 열 제목 클릭으로 서버 행 순서를 바꾸는 기능은 아직 구현하지 않았다.
- 행 정렬 기능을 추가할 때는 API가 지원하는 sort 필드·방향, URL, 첫 페이지 복귀를 함께 연결한다. 동작하지 않는 정렬 화살표를 표시하지 않는다.

## 6. 글자와 강조

- 업무 글자의 최소 크기는 14px이다. 보조 코드·날짜·순번·페이지 번호도 예외가 아니다. 모바일 입력은 16px을 유지한다.
- 표의 제품명은 14px·500, 코드는 별도 줄 14px·400이다. 보조색과 2px 간격으로 구분한다.
- 일반 상태는 높이 24px의 작은 배지와 텍스트로 표시한다. 배지 테두리에 상태색을 반복해서 두르지 않는다.
- 우선순위는 배경 상자 없이 방향 아이콘과 문자로 표현한다. 보통·낮음은 중립색, 높음은 앰버, 긴급은 적색이다.
- 지연 납기와 긴 차단 사유는 경고색 텍스트로 읽게 한다. 긴 문장 전체를 캡슐로 감싸지 않는다.
- 상태의 의미를 색상만으로 전달하지 않는다. 텍스트를 항상 남기며 독립적인 상태축을 합치지 않는다.
- 표 헤더는 14px·500, 본문 기본은 14px이다. 모든 셀을 굵게 만들지 않는다.
- 셀 padding은 가로 12px·세로 8px, 헤더는 가로 12px·세로 10px이다. 긴 이름은 행 높이를 자연스럽게 늘리되 잘라 숨기지 않는다.

## 7. 변경·검증 규칙

- 공용 규칙 변경은 이 문서와 [디자인 시스템](frontend-design-system.md)을 먼저 함께 갱신한다. 특정 페이지에만 다른 숫자·색·간격을 넣지 않는다.
- 새 표현은 대표 목록에서 확인한 뒤 공용 컴포넌트로 적용한다. 사용자 시각 검토 전에는 디자인 승인 완료로 기록하지 않는다.
- 단위 검사: No 내림차순, 페이지 경계, 현재 페이지 표식, 로딩 중 중복 이동, 조회조건 유지, 헤더·셀 정렬.
- 화면 검사: 1920·1440·390·320px, 라이트/다크, 한 페이지·여러 페이지·빈 결과, 표 내부 가로 스크롤과 하단 페이지네이션.
- 여러 페이지용 시험 데이터는 테스트 응답으로만 사용한다. 검증을 위해 생산·재고·품질 데이터를 생성하거나 수정하지 않는다.
- 온보딩의 실제 경로 이동·초점·반투명 배경·스크롤 안정성을 유지한다. 장식 변경 때문에 안내 동작을 재설계하지 않는다.
