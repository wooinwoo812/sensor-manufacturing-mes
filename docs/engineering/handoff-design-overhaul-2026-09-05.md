## 먼저 읽을 요약

- 대상은 이 저장소의 MES 웹입니다. 가상 제조 데이터로 업무 흐름을 보여 주는 포트폴리오이며 운영 배포·실제 고객 성과를 주장하지 않습니다.
- 최근 작업은 포트폴리오 검토에서 발견한 집계·시연 데이터·취소 정합성 수정과 로그인 단순화입니다. 로그인 전 안내 선택과 역할 재선택 문구를 제거해 역할 선택 후 바로 업무 화면으로 진입합니다. README는 실제 구현 범위·한계·코드·스크린샷·재현 절차를 연결합니다. 아래의 이전 로그인 안내 기록은 현재 화면 정책으로 사용하지 않습니다.

## 다음 작업과 주의사항

1. 실제 사용자 화면 검토와 포트폴리오 설명을 대조합니다. 정적 검사 통과만으로 사용성 승인을 대신하지 않습니다.
2. 큰 JavaScript 번들 경고와 브라우저 검사의 CI 편입은 별도 개선 과제입니다. 늦은 글꼴 교체는 아래 로딩 범위 정리에서 optional 정책으로 변경했습니다.
3. 실제 DB 경쟁·제약, 운영 보안·배포·백업 복구는 각 검증 환경에서 확인해야 합니다.
4. 서버 종료·재시드·커밋·PR·배포는 대상과 권한을 별도로 확인합니다. 이 기록에 명령이 있다는 이유로 자동 실행하지 않습니다.

## 포트폴리오 재검토와 로그인 단순화 · 2026-09-06

- 대시보드의 주간 시작을 서울 시간 월요일 0시로 수정했습니다. 일요일·월요일 0시·연말 경계와 조회 범위·요일별 집계를 검증했습니다. 진행 중과 전체 차단, 검사 대기와 보류 판정의 집계 범위를 문구에서도 구분합니다.
- WO-2026-094의 선행 검사 불합격을 후속 공정 차단에 반영했습니다. 완료 시연 공정에는 양품·불량·일시를 채우고 진행률은 등록된 공정 중 완료 비율로 맞췄습니다. 기존 시연의 일부 공정 이력과 신규 발행의 전체 경로는 README에서 구분합니다. 로컬 DB는 대상 기록의 JSON 백업 후 조건을 확인해 보정했으며 전체 seed를 다시 실행하지 않았습니다.
- 작업지시 취소와 활성 예약 해제·미완료 검사 취소·감사 기록을 같은 Serializable 트랜잭션으로 묶었습니다. 500자 취소 사유는 details에 보존하고 varchar(200) 요약만 제한합니다. 감사 저장 실패 시 취소가 남지 않는 HTTP 회귀와 실제 PostgreSQL 예약 해제 검증을 추가했습니다. 검사·부적합·자재 처분의 긴 감사 요약에도 같은 제한을 적용합니다.
- test:postgres 명령을 CI의 migration·seed 이후 필수 단계로 연결했습니다. 로컬 PostgreSQL에서 세 제품 생산 완료와 예약된 지시 취소 총 4개가 통과했으며 테스트 변경은 모두 롤백했습니다. API 일반 테스트 183개, Web 전체 499개와 추가된 문서 이미지 테스트, 루트 스크립트 28개를 검증했습니다. 원격 CI 실행 결과를 의미하지 않습니다.
- 사용자 피드백으로 로그인 전 안내 선택과 역할 재선택 상태 문구를 제거했습니다. 역할별 직접 로그인, 요청 중 중복 선택 방지, 실패 복구는 유지합니다. 실제 브라우저의 데스크톱·모바일 배치와 최고관리자 로그인 후 대시보드 진입을 확인했습니다.
- README에 구현 범위·한계·대표 코드·실제 화면·초기 migration/seed 절차를 연결했습니다. 공개 배포는 아직 없고 기간은 확인 가능한 Git 기록으로만 적었습니다. 업무 가이드에서도 저장소에 포함된 화면 이미지만 불러오도록 했습니다.

## 이전 로그인 안내 구성 · 2026-09-06

- 로그인에 프로젝트 목적과 가상 데이터 설명을 먼저 표시하고 안내받으며 시작을 추가했습니다. 안내 선택은 실제 역할 영역 강조·최고관리자 초점 이동만 수행하며 로그인 요청을 보내지 않습니다. 원하는 역할을 직접 누르면 로그인하고 해당 역할의 기존 안내를 이어갑니다. 배경을 가리는 새 팝업·스켈레톤·이미지는 추가하지 않았습니다.
- 로그인 전 동의는 인증 성공 후에만 일회성 선호로 인계합니다. 서버가 확인한 공개 역할 코드·버전·2분 만료만 저장하고 소비하며 세션·권한·사용자·업무 응답을 저장하지 않습니다. 이전 완료·건너뛰기 기록을 초기화하지 않으며 명시적으로 다시 선택한 경우에만 이어서 새 안내를 시작합니다. 직접 로그인에는 기존 초대 정책을 유지합니다.
- 미저장·저장 중 보호가 등록되기 전에 자동 안내가 시작할 수 있는 순서 문제를 집중 테스트에서 발견해, 본문 준비 후 취소 가능한 한 프레임 뒤 보호 상태를 확인하도록 수정했습니다. 저장소 차단·만료·다른 역할·로그인 실패에는 인증을 막거나 임의 업무 이동을 하지 않습니다. API·DB·역할 권한·서버 프로세스는 이번 작업에서 변경하지 않았습니다.
- Browser 스킬의 연결 도구를 사용할 수 없어 별도 테스트 브라우저를 사용했습니다. 로그인 안내 선택 전후 PC·모바일의 카드 위치·크기를 비교했고 8가지 화면 크기·테마·진입 사유 조합에서 최소 14px, 가로 넘침 없음, 자동 WCAG 검사 위반 0건을 확인했습니다. 버튼은 보이는 이름으로 접근하고 모바일에서도 최소 44px입니다.
- 인증과 로그인 안내 집중 테스트 59개를 통과했습니다. 원본과 캡처·검사 결과는 C:\Users\PC\mes-design-qa\login-entry-20260906에 있습니다. 이전 로그인 디자인 롤백은 이 변경 이후 파일 해시가 달라 중단되어야 하며, 새 작업의 백업을 기준으로 복원합니다. Git 전체 복원이나 DB 재시드를 사용하지 않습니다.

## 최고관리자 전체 업무 접근 · 2026-09-06

- 사용자는 모든 화면 조회뿐 아니라 등록·수정·업무 실행까지 가능한 최고관리자를 명시적으로 승인했습니다. 기존 SYSTEM_ADMIN의 표시명을 최고관리자로 바꾸고 대시보드를 시작 화면으로 지정했습니다. 새 여섯 번째 역할·계정·DB enum은 만들지 않았습니다.
- API ROLE_CONFIG에 정의된 23개 permission을 명시적으로 부여했습니다. 일반 네 역할의 permission은 기존 목록과 같음을 회귀 검사합니다. 서버의 공통 권한·CSRF·Origin·세션 검사, 제조 상태·수량·검사 게이트와 감사 기록, 마지막 활성 관리자 보호를 우회하지 않습니다. 구현 예정 3개는 여전히 실행 기능이 아닙니다.
- 로그인 첫 선택지와 안내를 최고관리자 중심으로 정리하고 세션 파서·시작 화면 라벨·권한표·감사 역할 표시·새로고침 메뉴 표시를 맞췄습니다. 사용자 역할 지정 시 최고관리자가 전체 업무 실행까지 허용한다는 설명을 제공합니다. 기존 로그인 디자인의 색상·카드·글자 크기는 유지했습니다.
- 최고관리자 화면 안내는 대시보드 → 작업지시 생성·상세 → 자재 예약·BOM·LOT → 공정 → 검사·부적합 → 계보 → 사용자·감사 → 대시보드의 28단계입니다. 실제 상태에 따른 입력 대체 영역, 섹션 강조, 동의·완료·건너뛰기 저장 키와 데이터 변경 금지는 유지합니다. 기존 관리자 설명의 역할 변경 불가 문구도 제거했습니다.
- API 162개, Web 462개, 초기 화면·문서·구조 스크립트 28개와 lint·typecheck·전체 build·문서 링크 검사를 통과했습니다. 여러 검사를 동시에 실행한 최초 Web 검사에서는 시간 초과와 후속 선택 오류가 있었고, 제한 시간을 늘리지 않은 maxWorkers=2 전체 재실행은 모두 통과했습니다. 큰 번들과 기존 LoginRoute 분할 경고는 별도 개선 과제입니다.
- Browser 스킬을 확인하고 연결된 제어 도구 대신 별도 테스트 브라우저에서 실제 API를 검증했습니다.
