## 6. 감시자(리뷰어) 체크리스트

이후 작업은 다른 사람이 하고, 리뷰어는 아래만 본다.

- 페이지 코드에 `mt-*`, `space-y-*`, 임의 padding 이 새로 들어왔는가 → 공용 컴포넌트로 옮긴다
- 조회 로직에 자체 `useEffect` 가 생겼는가 → `useLoadState` 를 쓴다
- 서버 코드(`MATERIAL_SHORTAGE` 같은 enum)가 화면에 그대로 보이는가 → entities 의 라벨 맵
- 새 상세 화면에 `PageCrumb`, `PageHeading.back`, `eyebrow` 가 있는가
- 배지가 두 줄로 꺾이거나 표가 1440px 에서 가로 스크롤을 만드는가
- 다크 모드에서 라이트와 같은 구조로 보이는가
- `corepack pnpm check` 가 경고 0 으로 통과하는가
- 디자인 결정을 바꿨으면 2.7 절 표에 한 줄(이유 포함)을 추가했는가

## 7. 2026-09-06 생산 흐름 수정

`fix/3-production-flow`에서 발행 후 공정·검사가 생성되지 않는 문제, 검사 합격 후 후속 공정이 차단된 채 남는 문제, 투입량과 맞지 않는 실적 저장, 작업지시 상세의 공정·검사 이동 누락을 수정했다. 발행된 BOM의 자재 필요량을 표시하고 예약·소비와 첫 공정의 준비 상태를 연결했다. 다음 공정의 투입량은 앞 공정의 양품 수량을 사용한다.

검증 결과: 웹 501개, API 172개, 저장소 구조·문서 관련 Node 검사 28개 통과. 기본 실행에서 제외되는 PostgreSQL 통합 검사 3개는 별도로 활성화하여 세 제품의 발행부터 완료까지 통과했다. 통합 검사의 작업지시·자재·재고·감사 기록은 트랜잭션 롤백으로 남기지 않았다. lint, Web/API 타입 검사와 빌드, Markdown 및 내부 링크 검사도 통과했다. Vite 빌드의 큰 청크 경고와 로그인 경로의 코드 분리 안내는 남아 있다.

실제 브라우저에서는 120개 투입 공정에 121개를 입력하면 완료 확정이 비활성화되는 것을 확인하고 취소했다. 작업지시 WO-2026-091에서 조립 2공정과 INSP-2026-0101 검사 상세가 같은 LOT로 연결되는 것도 확인했다. 기존 업무 기록을 브라우저에서 저장·판정·완료하지 않았다.

검증 범위와 재현 명령은 [검증 방법](testing-and-demo.md), 제품별 고정 경로·단일 LOT·이전 실적 누락·판정 정정의 한계는 [백엔드 구조](backend-architecture.md)를 따른다. DB 통합 검사는 순차 흐름 검증이며 운영 동시성·부하 검증으로 확대해서 설명하지 않는다.

## 8. 2026-09-06 로그인 안내와 실제 시작점

별도 소개 사이트는 사용자 피드백으로 중단했다. 소스는 작업 폴더에서 제외해 로컬 캐시에 보관했고, 미리보기 서버를 종료했다. 외부 배포·공개 전환은 하지 않았다. 이후 로그인 안내문과 역할 접기 방식도 사용자 피드백으로 교체했다. 현재 로그인은 짧은 제품·접속 설명 아래 최고관리자 ‘데모 둘러보기’와 네 가지 담당자 계정을 모두 표시한다. 담당자 계정은 데스크톱에서 2열, 모바일에서 1열로 배치하고 각 역할의 업무 설명과 시작 화면을 함께 제공한다. 접기 토글과 별도의 긴 보류 사례 소개문은 제거했다.

대시보드의 네 사례 카드는 ‘처음 살펴볼 작업’ 하나로 줄였다. API에서 현재 HOLD 검사와 작업지시를 연결해 선택하며, 보류가 해소되면 검토 후 완료 사례로 연결한다. 해당 사례가 없거나 취소됐으면 안내 링크를 만들지 않는다. 가상 사례는 create-portfolio-demo.mjs가 실제 업무 명령으로 생성한 네 작업이다. 로컬 생성 시 번호는 WO-2026-101~104였으며 UI는 이 번호를 하드코딩하지 않는다.

앞선 작업에서 검사 가능 조건과 보류 검토 명령, 최초·검토 판정 이력을 추가했다. PostgreSQL 검사 6개에서 세 제품의 완료 흐름, 예약 취소, 두 경쟁 보류 검토 중 하나만 커밋되는 조건, 감사 실패 시 원자성을 확인했다. 이는 전체 명령의 운영 부하 검증을 의미하지 않는다.

이번 로그인 안내 변경 후 Web 관련 검사 36개, 대시보드 API 검사 3개, 저장소 Node 검사 28개가 통과했다. Web/API 타입 검사, ESLint, Markdown·내부 링크 검사와 빌드도 확인했다. 브라우저에서 로그인 → 대시보드 시작점 → WO-2026-102 → IN-2026-102-01 검사 사유·판정 이력까지 실제 이동했으며 업무 판정은 변경하지 않았다. 390px 모바일 크기에서 로그인 가로 넘침이 없음을 확인하고 README의 로그인·대시보드·작업지시 이미지를 갱신했다. 기존 번들 크기 및 로그인 경로 코드 분리 안내는 남아 있다.
