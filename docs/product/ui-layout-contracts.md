## 1. 산출물 원칙

- 사용자 흐름, 화면 ID, 레이아웃과 상태 계약은 Markdown으로 version 관리한다.
- 저해상도 wireframe은 시각 장식이 아니라 정보 우선순위와 행동 위치를 검증한다.
- 실제 시각 완성도는 별도 mock을 만들지 않고 제품 React component에서 구현한다.
- 구현 PR은 정상·로딩·빈 값·오류·권한 없음·충돌 상태의 screenshot과 테스트를 남긴다.
- 문서와 실제 UI가 다르면 같은 PR에서 문서를 고치거나 차이의 이유를 기록한다.

## 2. 사용자 용어

| 의미 | 사용자 화면 | 코드·데이터 모델 |
|---|---|---|
| 생산 전에 자재 수량을 보류 | 자재 예약 | `MaterialAllocation` |
| 예약 자재를 생산에 실제 사용 | 실제 출고·투입 | `MaterialConsumption` + `InventoryTransaction` |
| 원자재에서 생산 결과 탐색 | downstream 영향 추적 | downstream trace query |
| 완제품에서 원자재 탐색 | upstream 원천 추적 | upstream trace query |

화면에서는 일관되게 `자재 예약`을 사용한다. 예약만으로 물리 재고 출고나 계보 관계가 생기지 않는다는 차이를 사용자가 용어만으로도 이해할 수 있어야 한다.

## 3. 전역 AppShell

### 3.1 1440px 이상

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 제품명 / 현재 역할                    마지막 갱신 14:32   검색   사용자 메뉴 │
├──────────────┬───────────────────────────────────────────────────────────────┤
│ 대시보드     │ 화면 제목                         [보조 행동] [대표 행동]   │
│ 생산         │ 조회 조건·필터·현재 대상 식별자                            │
│  작업지시    ├───────────────────────────────────────────────────────────────┤
│  공정 실행   │                                                               │
│ 자재         │                    화면별 업무 영역                           │
│ 품질         │                                                               │
│ 추적         │                                                               │
│ 관리         │                                                               │
├──────────────┤                                                               │
│ 도움말       │                                                               │
└──────────────┴───────────────────────────────────────────────────────────────┘
```

- sidebar는 1차 업무영역과 현재 위치를 표시한다.
- 대표 행동은 화면당 하나를 우선하며 오른쪽 상단에서 일관된 위치를 사용한다.
- 현재 역할과 마지막 데이터 갱신 시각은 전역에서 확인할 수 있다.
- 작업지시·자재 LOT·생산 LOT·완제품 일련번호는 전역 검색으로 진입한다.

### 3.2 1280px

- sidebar 너비를 줄이되 label을 icon만으로 대체하지 않는다.
- 본문 필수 열과 대표 행동을 유지하고 보조 정보는 상세 drawer로 이동한다.
- 표 전체가 아니라 열 우선순위에 따라 숨기며 사용자에게 숨겨진 열 수를 알린다.

### 3.3 현장 1024px

- `SCR-04A`·`SCR-04B`의 대상 식별자, 현재 공정, 핵심 수량과 대표 행동을 우선한다.
- 계획·품질·관리용 복합 표를 축소 복제하지 않는다.
- sidebar는 축소 가능하지만 현재 역할과 공정 대상은 항상 표시한다.

## 4. 역할 전환 데모 UX

5분 데모는 다섯 역할을 넘나들지만 client에서 역할 값만 바꾸지 않는다.

### `FLOW-AUTH-01` 원클릭 데모 로그인

```text
/demo-login
┌──────────────────────────────────────────────────────────────┐
│ 역할을 선택해 데모를 시작하세요                              │
│                                                              │
│ [생산계획] [현장 작업] [자재 담당] [품질 담당] [관리자]     │
│                                                              │
│ 모든 계정과 데이터는 가상이며 역할별 API 권한이 적용됩니다. │
└──────────────────────────────────────────────────────────────┘
```

1. 역할 카드를 선택하면 해당 seed 계정으로 실제 로그인 API를 호출한다.
2. server가 HttpOnly session cookie를 발급한다.
3. 원래 요청한 route가 새 역할에 허용되면 복귀하고, 허용되지 않으면 역할 홈으로 이동한다.
4. 역할 전환은 현재 session을 로그아웃한 뒤 새 로그인 API를 호출한다.
5. API permission guard와 AuditEvent의 actor는 새 server session을 기준으로 한다.

원클릭은 데모 입력을 줄이는 UX일 뿐 인증·권한 검증을 우회하는 기능이 아니다.

## 5. 핵심 화면 wireframe

### 5.1 `SCR-02A` 작업지시 목록

```text
┌ 작업지시 ──────────────────────────────────────── [작업지시 생성] ┐
│ 검색 [________] 상태 [전체▼] 납기 [이번 주▼] 우선순위 [전체▼]   │
├───────────────────────────────────────────────────────────────────┤
│ 번호       제품       계획수량  납기      진행률  현재공정  상태 │
│ WO-001     SEN-A      120       09-02     60%     조립      진행 │
│   차단 없음                                                     │
│ WO-002     SEN-B       40       09-01     20%     가공      보류 │
│   자재 MAT-02 부족 · [근거 보기]                                │
├───────────────────────────────────────────────────────────────────┤
│ 1–20 / 48                                      [이전] 1 2 3 [다음]│
└───────────────────────────────────────────────────────────────────┘
```

필수 열은 작업지시 번호, 제품, 계획수량, 납기, 진행률, 상태와 차단 사유다. 현재 공정과 우선순위는 1280px에서 상세 drawer로 이동할 수 있다. 행 전체를 클릭할 수 있으며 keyboard focus와 명시적 상세 링크를 함께 제공한다.

### 5.2 `SCR-02C` 작업지시 상세

```text
┌ WO-002 · SEN-B ─────────────── [보류] [자재 부족] [예약 화면으로] ┐
│ 계획 40    납기 09-01    생성자 계획담당자    version 7            │
├ 요약 ─ 자재 ─ 공정 ─ 검사 ─ LOT 계보 ─ 변경이력 ─────────────────┤
│                                                                    │
│ 진행 요약                     다음 행동                            │
│ [릴리스 완료]─[자재 준비 60%]  부족 자재 8개를 예약해야 시작 가능 │
│        └─────[공정 대기]        [SCR-03D 자재 예약으로 이동]       │
│                                                                    │
│ 차단 근거                                                          │
│ MAT-02 필요 20 / 예약 12 / 부족 8                                 │
└────────────────────────────────────────────────────────────────────┘
```

생산 진행, 최근 검사 판정과 현재 품질 disposition은 상세 header에서 서로 다른 label 그룹으로 표시한다. 하나의 종합 badge로 합치지 않는다.

### 5.3 `SCR-03D` 작업지시 자재 예약

```text
┌ WO-002 자재 예약 ─────────────────────────────────── [예약 저장] ┐
│ BOM revision B-03   계획수량 40   version 4                     │
├────────────────────────────┬─────────────────────────────────────┤
│ 필요 자재                 │ 선택 LOT                           │
│ MAT-01 필요 40 / 예약 40  │ LOT-M01  가용 25  [20]             │
│ MAT-02 필요 20 / 예약 12  │ LOT-M02  가용 12  [12]             │
│   부족 8                  │ LOT-M03  격리      선택 불가       │
│                            │                                     │
├────────────────────────────┴─────────────────────────────────────┤
│ 필요 60  기존 예약 32  이번 예약 0  부족 8                     │
│ 안내: 예약은 실제 출고·투입 또는 LOT 계보를 만들지 않습니다.   │
└──────────────────────────────────────────────────────────────────┘
```

- `onHand`, 예약, 가용량과 품질 disposition을 다른 열로 표시한다.
- 품질 차단 LOT는 선택할 수 없고 이유를 text와 icon으로 설명한다.
- 동시수정 충돌 시 최신 가용량, 내 요청량과 재시도 방법을 보여준다.

### 5.4 `SCR-04B` 공정 실행 — 1024px 기준

```text
┌ LOT-P002 · 공정 2/4 조립 ─────────────── [진행 중] [작업 종료] ┐
│ 작업지시 WO-002   작업자 현장-01   시작 14:05                  │
├────────────────────────────────────────────────────────────────┤
│ 공정 단계:  [가공 완료] ─ [조립 진행] ─ [검사 대기] ─ [포장] │
│                                                                │
│ 실제 투입 자재                                                 │
│ 예약 LOT-M01  예약잔량 20  이번 출고·투입 [ 20 ]              │
│                                                                │
│ 실적                                                           │
│ 투입수량 [ 20 ]   양품 [ 18 ]   불량 [ 2 ]                    │
│ 불량유형 [조립불량▼]  메모 [______________________________]    │
│                                                                │
│ 검증: 투입수량 = 양품 + 불량                                  │
│                                              [임시저장] [완료] │
└────────────────────────────────────────────────────────────────┘
```

실제 투입을 포함한 공정 시작이 실패하면 예약잔량, 재고, 소비, 계보, 공정과 감사 기록이 모두 원래 상태로 남아야 한다. 오류 메시지는 실패한 계약과 해결 행동을 표시한다.

### 5.5 `SCR-05B` 검사 실행과 `SCR-05C` 부적합·격리

```text
┌ LOT-P002 최종검사 ───────── 규격 Q-FINAL rev.4 ─────── [판정] ┐
│ 항목        측정값      단위    허용범위         결과          │
│ 출력전압    [ 4.98 ]    V       4.90–5.10        합격          │
│ 외관        [정상▼]     -       정상             합격          │
│ 절연저항    [_____]     MΩ      100 이상         필수값 누락   │
│                                                                │
│ 현재: 생산 진행 [공정 완료]  검사 [미완료]  품질 [PENDING]    │
└────────────────────────────────────────────────────────────────┘

┌ 원자재 부적합 사건 QI-004 ─────────────────────── [영향 조회] ┐
│ 원천 LOT-M01   발견일 09-03   사유 [시험 결과 이상]           │
│                                                                │
│ 영향 대상                  생산 진행   검사      품질 상태     │
│ LOT-P002                   완료        합격      격리 예정     │
│ UNIT-S002-01               완료        합격      격리 예정     │
│                                              [선택 대상 격리] │
└────────────────────────────────────────────────────────────────┘
```

검사 화면은 적용 revision과 판정 snapshot을 보여준다. 사후 부적합 화면은 `생산 완료 / 최종검사 합격 / 현재 격리`를 동시에 읽을 수 있어야 하며 과거 완료·판정을 덮어쓰지 않는다.

### 5.6 `SCR-06B` LOT·일련번호 계보

```text
┌ 계보 추적 ─ [LOT-M01________________] [검색]                   ┐
│ 방향 [downstream▼] 깊이 [3▼] 상태 [전체▼]                    │
├──────────────────────────────┬─────────────────────────────────┤
│ 단계별 tree                 │ 선택 관계 상세                  │
│ LOT-M01 자재                │ 관계 CONSUME                    │
│ └─ LOT-P001 생산            │ 수량 20                         │
│    ├─ LOT-P001-A 분할       │ 발생 event EVT-104              │
│    │  └─ UNIT-S001-01       │ 작업지시 WO-001                 │
│    └─ LOT-P001-B 분할       │ 시각 09-01 14:05                │
│       └─ UNIT-S001-02       │ [업무 기록으로 이동]            │
├──────────────────────────────┴─────────────────────────────────┤
│ [동등한 table 보기]  결과 5개  부분 이력 0개                  │
└────────────────────────────────────────────────────────────────┘
```

- tree와 동일한 정보를 table로 탐색할 수 있다.
- 원자재 기준은 downstream 영향, 완제품 기준은 upstream 원천을 기본값으로 사용한다.
- 대량 결과는 단계별 펼치기와 server pagination을 사용한다.
- 부분 이력이나 삭제된 참조는 숨기지 않고 불완전한 근거임을 표시한다.

## 6. 상태 표현 계약

### 6.1 세 상태 축

| 축 | 질문 | 예시 | 표현 위치 |
|---|---|---|---|
| 생산 진행 | 제조가 어디까지 진행됐는가? | 계획, 준비, 진행 중, 완료 | 대상 header·공정 stepper |
| 최근 검사 판정 | 마지막 유효 검사의 결과는 무엇인가? | 미검사, 합격, 불합격, 보류 | 검사 summary·대상 header |
| 품질 disposition | 지금 사용·완료·출하 가능한가? | PENDING, ACCEPTED, HOLD, QUARANTINED, REJECTED | 대상 header·모든 관련 목록 |

세 축은 동시에 표시할 수 있지만 하나의 badge나 종합 상태 문자열로 합치지 않는다.

```text
생산 진행  [완료 ✓]    최종검사  [합격 ✓]    현재 품질  [격리 !]
```

각 label은 색상 없이 text와 icon만으로도 의미와 심각도를 구분할 수 있어야 한다.

### 6.2 공통 화면 상태

| 상태 | 보존할 문맥 | 필수 행동 |
|---|---|---|
| 로딩 | 화면 제목·조회 조건·기존 데이터 | 중복 명령 차단, 영역 단위 진행 표시 |
| 빈 값 | 현재 filter와 권한 | 첫 생성 또는 filter 초기화 |
| 오류 | 실패한 명령·사용자 입력·요청 ID | 안전한 재시도 또는 입력 수정 |
| 권한 없음 | 대상과 필요한 권한 | 역할 전환 또는 이전 화면 이동 |
| 충돌 | 내 입력과 최신 version | 최신값 조회 후 명시적 재시도 |
| 부분 실패 | 성공·실패 대상 구분 | 실패 대상만 재처리 |

## 7. 반응형 열·행동 우선순위

| 화면 | 1440px 이상 | 1280px | 현장 1024px |
|---|---|---|---|
| `SCR-02A` | 모든 핵심·보조 열 | 번호·제품·수량·납기·진행·상태·차단 유지 | 지원 대상 아님 |
| `SCR-02C` | 탭과 요약·다음 행동 병렬 | 다음 행동을 상단, 보조 metadata 접기 | 읽기 전용 핵심 요약 |
| `SCR-03D` | 필요 자재와 선택 LOT 병렬 | 두 영역 유지, 보조 LOT 열 숨김 | 지원 대상 아님 |
| `SCR-04B` | 단계·자재·실적 병렬 가능 | 실적 입력 우선 | 핵심 입력과 완료 행동 한 화면 유지 |
| `SCR-05B` | 검사 항목·판정 summary 병렬 | 필수 항목과 기준 유지 | 지원 대상 아님 |
| `SCR-06B` | tree와 상세 병렬 | 상세 drawer 전환 | table 중심 읽기 전용 |

가로 스크롤이 필요한 원자료 열은 상세 drawer 또는 사용자가 명시적으로 연 table에만 허용한다. 대표 행동과 차단 사유를 보기 위해 가로 스크롤하도록 만들지 않는다.
