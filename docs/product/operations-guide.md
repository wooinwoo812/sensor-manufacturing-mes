# MES 업무 안내

이 안내는 생산·자재·품질·문서 확인 담당자가 같은 기록을 읽기 위한 공통 안내다.
현재 화면의 데이터는 가상 데모 데이터이며 실제 제조 실적이나 공식 증빙으로 사용하지 않는다.
문서는 모든 로그인 역할이 읽을 수 있지만, 실제 업무 화면과 실행 권한은 현재 역할에 따라 다르다.

## 처음 들어오면

1. 상단과 왼쪽 하단의 현재 역할을 확인한다. 다른 담당자의 권한을 대신 사용하지 않는다.
2. 왼쪽 메뉴에서 업무를 고른다. 보이지 않는 메뉴는 현재 역할의 권한 범위 밖일 수 있다.
3. 상단 사용 안내를 눌러 실제 화면 둘러보기를 시작한다. 시작 여부를 먼저 묻고 안내 중에는 저장·판정·완료를 실행하지 않는다.
4. 목록에서는 조건을 고른 뒤 조회를 누른다. 조건을 편집하는 것만으로 결과가 바뀌지는 않는다.
5. 행을 눌러 상세의 업무 번호·제품·수량·상태·변경 이력을 대조한다.

## 기록을 읽는 업무 순서

| 단계      | 확인할 화면                      | 반드시 대조할 기록                                                 |
| --------- | -------------------------------- | ------------------------------------------------------------------ |
| 생산 계획 | 작업지시                         | 작업지시 번호, 제품 코드, 계획수량, 단위, 납기, 우선순위           |
| 자재 준비 | BOM 기준정보·자재 LOT·자재 예약  | 적용 revision, 구성 자재, 품질 상태, 재고·예약·가용 수량, 유효기간 |
| 현장 실행 | 공정 실행·공정 상세              | 생산 LOT, 공정 순서, 준비/차단 상태, 투입·양품·불량 기록           |
| 검사      | 검사 목록·상세                   | 검사 번호, 대상 LOT·공정, 실행 상태, 판정, 보류·불합격 사유        |
| 예외 대응 | 부적합·격리                      | 사건 번호, 발생 원천, 영향 범위, 격리 대상, 처분·해제 이력         |
| 추적·감사 | LOT 계보·각 상세의 이력·감사이력 | 자재→생산→완제품 연결, 행위자, 시각, 사유, 대상 번호               |

문서 확인 업무는 위 순서로 식별자와 기록을 대조한다. 화면에 없는 승인·서명·출력 완료를 완료한 것으로 기록하지 않는다.
현재 웹에는 별도의 문서 결재, 전자서명, 공식 서식 발급 기능이 없다.

## 메뉴별로 무엇을 보는가

| 메뉴         | 용도                                      | 혼동하지 않을 점                                                            |
| ------------ | ----------------------------------------- | --------------------------------------------------------------------------- |
| 대시보드     | 운영 현황과 조치가 필요한 항목 파악       | 마지막 조회 시점의 요약이며 상세 기록이 근거다                              |
| 작업지시     | 생산 계획과 작업 진행의 기준 확인         | 초안 생성과 발행은 다르다. 높은 우선순위가 차단을 해제하지 않는다           |
| 공정 실행    | 시작할 작업과 진행 중 작업 확인           | 준비 상태와 생산 완료 상태는 다르다                                         |
| BOM 기준정보 | 제품에 적용되는 구성 자재와 revision 확인 | 최신 revision과 이미 발행된 작업의 적용 revision을 임의로 같게 보지 않는다  |
| 자재 LOT     | 입고·재고·예약·가용 수량과 품질 상태 확인 | 재고가 있어도 예약·격리·유효기간 때문에 사용할 수 없을 수 있다              |
| 검사         | 검사 실행과 판정 확인                     | 검사 완료와 합격은 같은 의미가 아니다                                       |
| 부적합·격리  | 품질 사건과 영향 대상의 대응 확인         | 사건 상태와 개별 대상의 처분은 독립적인 기록이다                            |
| LOT 계보     | 투입 자재부터 생산·완제품의 연결 확인     | 이름이 비슷해도 같은 LOT이라고 추측하지 않는다                              |
| 감사이력     | 누가 언제 무엇을 바꿨는지 확인            | 통합 감사 조회는 관리자 권한이다. 다른 역할은 허용된 상세의 이력을 확인한다 |
| 사용자       | 사용자 역할 지정·활성 상태·변경 이력 확인                   | 최고관리자 부여는 전체 업무 실행 권한까지 주므로 대상을 확인한다                     |

## 사용자 역할과 사용 상태 변경

최고관리자는 사용자 화면의 관리 버튼에서 기존 다섯 역할 중 하나와 활성 상태를 선택한다. 사유를 적고 변경 내용을 확인한 뒤 확정한다. 권한 조합을 직접 편집하는 화면은 아니다. 역할별 권한 탭은 읽기 전용이며 구현 예정 표시는 아직 실행할 수 있는 기능이 아니다.

변경하면 대상 계정의 기존 로그인이 모두 종료된다. 자기 계정을 변경했다면 다시 로그인한다. 마지막 활성 관리자를 해제하거나 비활성화할 수 없다. 여러 역할이 있던 계정은 선택한 역할 하나로 바뀌므로 확인 문구를 읽는다. 변경 전후 내용·사유·담당자는 변경 이력에서 확인한다.

목록이 오래됐거나 저장 결과가 불명확하면 연달아 저장하지 말고 창을 닫아 목록과 이력을 다시 확인한다. 실행 환경에 새 DB 변경과 API가 적용되기 전에는 관리 기능을 사용할 수 없다.

## 역할별 시작점

| 현재 역할     | 시작 화면 | 주로 확인·수행하는 업무                             |
| ------------- | --------- | --------------------------------------------------- |
| 생산계획      | 작업지시  | 계획·수량·납기 확인, 허용된 작업지시 생성·발행·취소 |
| 자재          | 자재 LOT  | 재고·품질 상태 확인, 자재 예약과 해제               |
| 현장 작업자   | 공정 실행 | 실행 가능한 공정 확인, 시작과 실적 입력             |
| 품질          | 검사      | 검사·판정, 부적합·격리와 허용된 품질 처분           |
| 최고관리자 | 대시보드 | 전체 화면 조회·업무 실행, 사용자 권한·감사 관리 |

전체 화면을 한 번에 검토하려면 로그인 첫 번째 선택지인 최고관리자로 시작한다. 작업지시 생성·발행·취소, 자재 예약·해제·품질 결정, 공정 시작·완료, 검사 판정·부적합 등록까지 사용할 수 있다. 조회와 달리 이 행동들은 실제 데모 기록을 바꾸므로 둘러보기 중에는 실행하지 않는다. 최고관리자도 상태·수량·검사 차단 조건을 건너뛰지 못하며, 구현 예정인 기능이 새로 제공되는 것은 아니다.

문서 담당자라는 별도 역할은 현재 정의되어 있지 않다. 필요한 실제 데이터 접근은 관리자에게 권한 범위를 확인한다.
가이드를 읽는 것과 업무 데이터를 조회하거나 수정할 권한을 갖는 것은 별개다.

## 목록·검색·페이지 읽기

- 검색어와 선택 조건을 입력한 뒤 조회 또는 Enter로 적용한다. 한글 입력을 확정하는 Enter는 조회하지 않는다.
- 조건 초기화는 검색조건을 지우고 첫 페이지로 돌아간다. 선택한 표시 건수는 유지한다.
- 기본은 10건씩 보기다. 표 하단에서 10·20·50·100건으로 바꿀 수 있다. 건수를 바꾸면 적용된 조건을 유지하고 첫 페이지로 돌아간다.
- No는 조회 결과의 표시 순번이다. 전체 건수부터 역순으로 내려가며 실제 작업지시 번호나 등록 순서가 아니다.
- 수량·비율·날짜·상태는 가운데, 식별자·제품·설명은 왼쪽 정렬한다.
- 제품명 아래의 제품 코드를 함께 확인한다. 이름이 비슷할 때 코드를 생략하지 않는다.
- 열 제목 클릭으로 행 순서를 바꾸는 기능은 아직 없다. 셀 정렬과 조회 순서 변경은 서로 다르다.
- 작은 화면에서 표만 좌우로 이동한다. No와 첫 식별 열은 위치 확인을 위해 고정한다.

자세한 기준은 [목록 화면·테이블 규칙](../engineering/frontend-table-rules.md)을 따른다.

## 상태와 용어

| 용어      | 읽는 방법                                                                      |
| --------- | ------------------------------------------------------------------------------ |
| LOT       | 같은 추적 단위로 묶인 자재 또는 생산 기록. 종류와 표시번호를 함께 확인한다     |
| BOM       | 제품 구성 자재와 소요 기준. 적용 revision을 확인한다                           |
| Revision  | 기준정보의 판. 변경 전후 기록을 구분한다                                       |
| 가용 수량 | 현재 사용할 수 있는 수량. 전체 재고와 같다고 가정하지 않는다                   |
| 차단      | 다음 업무를 진행할 수 없는 조건. 자재 부족·검사·품질 등의 사유를 먼저 확인한다 |
| 보류      | 판정·진행을 유보한 상태. 합격이나 해제를 뜻하지 않는다                         |
| 격리      | 사용·이동 등에 제한을 둔 품질 처분. 생산 완료 여부와 별도로 확인한다           |
| 실행 상태 | 검사나 공정 업무가 얼마나 진행됐는지 나타내는 상태                             |
| 판정      | 검사 결과. 실행 완료와 별개의 축이다                                           |
| 감사 이력 | 변경 행위의 대상·행위자·시각·사유 기록                                         |

색상만으로 판단하지 말고 상태 문자와 사유를 함께 읽는다. 생산 완료·검사 판정·품질 처분을 하나의 정상 표시로 합치지 않는다.

## 기록 확인 체크리스트

1. 현재 역할과 조회 화면이 맞는가?
2. 작업지시·LOT·검사·사건 번호가 원본 기록과 일치하는가?
3. 제품 코드, 적용 revision, 수량과 단위를 함께 확인했는가?
4. 납기·발생 시각·기록 시각을 서로 다른 값으로 구분했는가?
5. 생산 진행, 검사 판정, 품질 처분을 각각 확인했는가?
6. 차단·보류·격리 사유와 후속 기록이 있는가?
7. 추적 연결과 변경 이력을 대조했는가?
8. 불일치 사항은 대상 번호·화면·조건·발생 시각과 함께 담당자에게 전달했는가?

## 조회 실패·권한·저장 주의

- 결과가 없으면 조건과 대상 번호를 먼저 확인한다. 빈 결과를 조회 장애로 단정하지 않는다.
- 조회 오류에는 다시 시도를 사용한다. 여러 번 빠르게 눌러 같은 요청을 쌓지 않는다.
- 권한이 없으면 허용된 시작 화면으로 돌아가 필요한 업무 범위를 관리자와 확인한다.
- 저장·판정·완료는 실제 업무 기록을 바꾼다. 읽기·둘러보기 목적이라면 실행하지 않는다.
- 저장 실패를 성공으로 기록하지 않는다. 입력과 오류 내용을 확인하고 안내된 복구 절차를 따른다.
- 미저장 입력을 남기고 화면을 떠날 때는 이동 확인 문구를 읽는다.

## 이 가이드와 디자인 문서

업무 설명은 이 문서, 목록 표현은 [화면 규칙](../engineering/frontend-table-rules.md), 색상·서체·공용 컴포넌트는 [디자인 시스템](../engineering/frontend-design-system.md), 구현 책임은 [프런트엔드 구조](../engineering/frontend-architecture.md)가 소유한다.
웹 가이드는 저장소의 같은 원문을 읽는다. 화면용 설명을 별도 복사본으로 관리하지 않는다.
